# Architecture rules
- Wrap routes in HelmetProvider and Suspense; lazy-load secondary pages so metadata and loading states work without loading every tool initially.
- Keep the SWMM engine in a worker, read continuity errors from reports, and bound pending requests with timeouts because the bundled glue does not expose heap views.
- Keep calculator mathematics in testable pure helpers and present water-budget recharge separately from its baseflow partition to avoid double-counting.
- Only display chapter-related external articles after verifying their destinations, and label application-authored takeaways as paraphrases rather than source quotations.
- Keep the Playground model builder's INP writing and validation in a pure helper so generated files stay testable apart from the drawing canvas.
- Draw Playground ensemble samples only from the seeded sampler helper so a recorded master seed reproduces every run; never use Math.random for model inputs.
- Label app-authored numeric rules, scores and case studies as illustrative unless a verifiable source is cited.
- Record each user-visible release in the What's New changelog data (newest first, dates from project history) because the footer's last-updated date is derived from it.
- Store Model Library .inp files in the visitor's browser (IndexedDB) through the modelLibrary helper, because the app has no sign-in and model files can exceed localStorage quotas.
- Generate worked-case observations from a hidden parameter set plus seeded noise in the workedCase helper, and label the case and its targets as fictional and illustrative, so the example stays reproducible and never passes as real data.
- Ground Ask James answers in the app's own chapter summaries picked by the chatSources helper and shown as numbered, clickable citations labelled as app summaries, because the app holds no verified text of the 2005 book.
